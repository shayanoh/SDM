# Rust Core Under the SwiftUI App — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers run on Sonnet 5.5; reviews are batched at the marked **Review gate** points, not after every task.

**Goal:** Port the four `SDMKit` Swift targets to a Rust workspace, run the existing SwiftUI app on it through UniFFI bindings, and record CPU and memory against the Swift core.

**Architecture:** A Cargo workspace at `sdm-core/` with four library crates mirroring today's targets, an `sdm-ffi` crate exposing three objects and the domain records through UniFFI, and a build script that turns it into an XCFramework. `SDMKit/` becomes a thin Swift package of generated bindings and re-export shims. The original Swift package survives at `legacy/SDMKitSwift/` as the baseline.

**Tech Stack:** Rust (stable, 2024 edition), tokio, reqwest + rustls, serde, UniFFI (proc-macros), Swift 6.2, Xcode 26.

**Spec:** `docs/superpowers/specs/2026-10-12-rust-core-design.md` — read it in full before any task. Roadmap: `docs/rust-migration-roadmap.md`.

## Global Constraints

Every task's requirements include all of these.

**This is a port.** The Swift source is the specification. Read the whole Swift file before writing its Rust twin. Reproduce behavior exactly, including behavior that looks odd; do not fix, simplify, or redesign. If the Swift looks like a bug, port it as is and list it under "Concerns" in your report. Carry the Swift doc comments across (translated to Rust idiom where they name Swift constructs), because they record why the code is the way it is.

**File mapping.** `Foo.swift` → `foo.rs` in the matching crate, one type family per file, same type names, `snake_case` functions. `FooTests.swift` → `crates/<crate>/tests/foo_tests.rs` (or a `#[cfg(test)] mod tests` inside `foo.rs` when the test needs private items), same test names in `snake_case`. Shared test helpers go in `crates/<crate>/tests/support/mod.rs`. A Swift `@Test(arguments: [...])` becomes one Rust test looping over the same table.

**Concurrency translation (spec §4) — follow exactly:**

- Swift `actor` → `pub struct Foo { inner: Arc<FooInner> }` with `state: std::sync::Mutex<FooState>`. Lock for each synchronous stretch between Swift suspension points; **never hold a lock across `.await`**. Never substitute `tokio::sync::Mutex`.
- Swift `Task { }` → `tokio::spawn`. Swift `task.cancel()` → `tokio_util::sync::CancellationToken::cancel()`, checked where Swift checks `Task.isCancelled` / `try Task.checkCancellation()`. Never `JoinHandle::abort()`.
- `withTaskGroup` / `withThrowingTaskGroup` → `tokio::task::JoinSet`.
- `AsyncThrowingStream<Data, Error>` → `Pin<Box<dyn futures::Stream<Item = Result<bytes::Bytes, E>> + Send>>`.
- Injected protocols → `#[async_trait::async_trait] pub trait Foo: Send + Sync`, held as `Arc<dyn Foo>`.
- `CheckedContinuation` wake-ups → `tokio::sync::Notify` or a `oneshot` channel.

**Type translation (spec §5):** `UUID` → `uuid::Uuid`; `URL` → `url::Url`; `Data` → `bytes::Bytes` for streamed bodies, `Vec<u8>` otherwise; `Date` → `std::time::SystemTime`; `TimeInterval` → `f64`; `Duration` → `std::time::Duration`; `Int` → `i64` where it is a byte count or persisted, `usize` for in-memory counts and indices; `Int64` → `i64`; `Bool?` → `Option<bool>`; Swift `throws` → `Result<T, E>` with a `thiserror` enum named like the Swift error. `precondition` → `assert!`; `fatalError` → `panic!`.

**Persistence compatibility (spec D5):** every `Codable` type gets `serde` (de)serialization that reads what Swift writes and writes what Swift reads. Check the Swift `CodingKeys`, custom `init(from:)` / `encode(to:)`, and that Swift omits `nil` optionals (`#[serde(skip_serializing_if = "Option::is_none")]`, `#[serde(default)]`). Swift-written fixtures live in `sdm-core/fixtures/swift/` (Task 3).

**No test touches the network or sleeps on a real clock.** Time advances by calling `tick()`. Loopback (`127.0.0.1:0`) servers inside the test process are allowed for transport tests only. Tests use `#[tokio::test(flavor = "multi_thread", worker_threads = 4)]` unless they need `tokio::time::pause()`, which requires the default current-thread flavor.

**Dependencies** are added only with `cargo add` (never by hand-editing `Cargo.toml` dependency tables; workspace-level settings such as `[workspace.lints]` are hand-written because no command writes them). Before using any crate's API, check its current documentation with the Context7 MCP tools (`resolve-library-id`, then `query-docs`) — do not write library calls from memory.

## Review Focus

Failure modes the spec implies that ordinary ported tests may not exercise. Each is pinned by a test in the named task.

1. **A `state.json` written by the shipping Swift app loads, and what Rust writes back loads in Swift** — including legacy flat-shape items and items with every optional field absent. (Task 5 and Task 12, fixtures from Task 3.)
2. **A URL with characters `url::Url` would re-encode or normalize (uppercase host, default port, unescaped spaces, non-ASCII path, trailing dot, empty query) survives persistence byte for byte and still de-duplicates against itself.** (Task 5, Task 22.)
3. **Cancelling a download mid-write never leaves bytes on disk that the `RangeSet` does not record, and never records bytes that were not written** — the byte-identity-under-churn property with pause, kill and segment-count changes interleaved. (Task 14, Task 19.)
4. **An origin that redirects, drops mid-body, lies about `Content-Length`, or ignores `Range` behaves through `reqwest` as it did through `URLSession`.** (Task 13.)
5. **Calling into the engine from Swift while a tick is in flight neither deadlocks nor panics across the FFI boundary** — every exported method returns under concurrent calls, and a Rust panic cannot unwind into Swift. (Task 23.)
